## 1. Introducción

La presente evidencia documenta la entrega de los módulos integrados del sistema web **Divina Providencia**, desarrollado como parte del proceso formativo del programa Tecnólogo en Análisis y Desarrollo de Software.

La solución corresponde a una aplicación FullStack conformada por un frontend desarrollado con React y Vite, una API REST implementada con Spring Boot y una base de datos compatible con MySQL.

Los módulos principales entregados son:

- autenticación de usuarios;
- gestión de alojamientos;
- gestión de reservas.

Estos componentes fueron desarrollados e integrados dentro de una misma solución, utilizando servicios HTTP para la comunicación entre el frontend y el backend y mecanismos de persistencia mediante Spring Data JPA.

La evidencia incluye el código fuente almacenado en un repositorio Git, los archivos compilados del frontend y backend, las URLs públicas de los módulos desplegados, la documentación de entradas y salidas, los resultados de las pruebas ejecutadas, las configuraciones utilizadas en los diferentes ambientes y el manual técnico correspondiente.

## 3. Requerimientos del sistema

Para la integración del sistema **Divina Providencia** se consideraron los requerimientos funcionales y técnicos asociados a los módulos desarrollados.

Los requerimientos se definieron de acuerdo con las funcionalidades implementadas y verificadas durante el desarrollo del proyecto.

### 3.1 Requerimientos funcionales

#### RF-01 Registro de usuarios

El sistema debe permitir registrar usuarios mediante un nombre de usuario y una contraseña.

La contraseña debe ser procesada antes de su almacenamiento y no debe conservarse directamente en texto plano.

#### RF-02 Inicio de sesión

El sistema debe permitir validar las credenciales de un usuario registrado.

Las credenciales correctas deben generar una respuesta satisfactoria y las credenciales incorrectas deben ser rechazadas.

#### RF-03 Consulta de alojamientos

El sistema debe permitir consultar los alojamientos registrados mediante la API REST.

La información debe incluir como mínimo:

- identificador;
- nombre;
- descripción;
- capacidad;
- precio por noche;
- disponibilidad.

#### RF-04 Visualización de alojamientos

El frontend debe mostrar dinámicamente los alojamientos obtenidos desde el backend.

La información no debe depender únicamente de registros estáticos definidos directamente en React.

#### RF-05 Selección de alojamiento

El usuario debe poder seleccionar un alojamiento desde la interfaz para utilizarlo durante el proceso de reserva.

#### RF-06 Registro de reservas

El sistema debe permitir registrar reservas asociadas a un alojamiento existente.

La reserva debe incluir:

- nombre del huésped;
- correo electrónico;
- fecha de entrada;
- fecha de salida;
- número de huéspedes;
- estado;
- alojamiento asociado.

#### RF-07 Validación de reservas

El sistema debe verificar que el alojamiento indicado exista antes de registrar una reserva.

El frontend también debe validar los datos principales del formulario antes de enviar la solicitud.

#### RF-08 Consulta y gestión de reservas

El backend debe permitir consultar reservas y realizar operaciones de actualización o eliminación mediante los servicios definidos por la API.

#### RF-09 Persistencia de información

Los usuarios, alojamientos y reservas deben almacenarse de forma persistente mediante una base de datos compatible con MySQL.

### 6.1.1 Registro de usuario

**Método HTTP**

```text
POST
```

**Endpoint**

```text
/api/auth/register
```

#### Datos de entrada

El frontend envía las credenciales del usuario en formato JSON.

Ejemplo:

```json
{
  "username": "ga8_public_user",
  "password": "********"
}
```

| Campo | Tipo | Descripción |
|---|---|---|
| username | String | Nombre utilizado para identificar al usuario |
| password | String | Contraseña proporcionada por el usuario |

La contraseña se muestra oculta en esta documentación y no se registra como evidencia.

#### Procesamiento

El backend realiza las siguientes operaciones:

```text
Recibe credenciales
       ↓
Verifica existencia del usuario
       ↓
Codifica contraseña
       ↓
Crea entidad User
       ↓
Guarda usuario
```

La contraseña no es almacenada directamente en texto plano.

#### Datos de salida

Cuando el registro finaliza correctamente, el frontend recibe una respuesta que permite mostrar:

```text
Usuario registrado correctamente.
```

#### Resultado de validación

```text
Registro de usuario: APROBADO
```

La operación también fue validada desde la aplicación desplegada públicamente.
